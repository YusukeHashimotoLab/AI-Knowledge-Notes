2.1 プランナーの仕事

ループの各周回でプランナーが直面する問いは常に同じです: これまでの測定結果を踏まえて、どの実験が最もコストに見合うか? 答えは 2 つの部品で構成されます:

  1. 代理モデル（サロゲートモデル） — 高価な実験の安価な統計的代役。未試行の条件に対して予測値と不確かさを返す
  2. 獲得関数 — 予測値と不確かさを組み合わせ、候補実験に「有望さ」の点数を付ける規則
flowchart LR A["測定データ(x, y) ペア"] --> B["代理モデル予測 + 不確かさ"] B --> C["獲得関数全候補を採点"] C --> D["次の実験最高スコア"] D --> A

この機構はベイズ最適化シリーズで詳しく扱っています。本章では、最適化器がロボットの中に入ると何が変わるかに焦点を当てます。

2.2 代理モデル

主力はガウス過程（GP）です。任意の候補 x に対し、平均予測 μ(x) と標準偏差 σ(x) を返します。SDL の実務で GP が支配的な理由:

  • 獲得関数が必要とする不確かさを誠実に定量化する
  • 高価な実験に典型的な小規模データ（数十〜数百点）でよく機能する
  • その滑らかさの仮定が多くのプロセス–物性地形に合う

状況が求めれば代替手段も使われます: カテゴリ変数と連続変数が混在する空間（例: 溶媒の種類 + 温度）にはランダムフォレスト、データが数千件に育てばニューラルネットワークのアンサンブル。原則は変わりません — プランナーには予測値と誤差棒の両方が必要です。

from sklearn.gaussian_process import GaussianProcessRegressor
from sklearn.gaussian_process.kernels import Matern

gp = GaussianProcessRegressor(kernel=Matern(nu=2.5), normalize_y=True)
gp.fit(X_measured, y_measured)
mu, sigma = gp.predict(X_candidates, return_std=True)   # 予測 + 不確かさ

2.3 獲得関数: 不確かさの下での意思決定

獲得関数は (μ, σ) を 1 つの「有望さ」スコアに変換します。古典的な 3 つ:

獲得関数 式（概形） 性格
期待改善量（EI） E[max(y − y_best, 0)] バランス型の定番。多くの SDL キャンペーンが採用
上側信頼限界（UCB） μ + κσ 調整可能: κ 大で探索、κ 小で活用
改善確率（PI） P(y > y_best) 貪欲。確実だが微小な改善に停滞しうる

本質的な緊張関係は探索と活用です。σ が大きい場所のサンプリングはモデルに最も多くを教え、μ が高い場所のサンプリングは今すぐ性能を刈り取ります。純粋に貪欲なループは局所最適に囚われ、純粋に探索的なループは勝ち目のない領域の地図作りに予算を浪費します。

import numpy as np
from scipy.stats import norm

def expected_improvement(mu, sigma, y_best, xi=0.01):
    z = (mu - y_best - xi) / sigma
    return (mu - y_best - xi) * norm.cdf(z) + sigma * norm.pdf(z)

scores = expected_improvement(mu, sigma, y_measured.max())
x_next = X_candidates[np.argmax(scores)]

能動学習と最適化の違い

すべてのキャンペーンが単一の最適点を狩るわけではありません。目的が空間全体の正確なモデル（相図、校正曲面）であれば、プランナーは性能ではなく情報量を最大化すべきです — 予測の不確かさが最大の点、あるいは期待されるモデル変化が最大の点を選びます。これが能動学習であり、専用シリーズで扱っています。実際の SDL キャンペーンの多くは両モードを織り交ぜます: まず地図を作り、次に最適化する。

2.4 バッチ計画: 並列ハードウェアに実験を供給する

ロボットプラットフォームが試料を 1 つずつ処理することは稀です — プレートには 24 穴や 96 穴があり、電気炉は複数のるつぼを同時に焼成します。プランナーは、どの結果も見る前に q 個の実験のバッチを提案しなければなりません。獲得スコア上位 q 個を素朴に取る方法は失敗します: 上位スコアは同じピークの周りに密集し、バッチをほぼ重複した実験で浪費してしまうのです。

標準的な解決策:

  • Kriging Believer（幻想点方式）: 最良候補を選び、その予測値が測定されたことにしてモデルを再学習し、次を選ぶ — これを q 回。幻想点が近傍の不確かさを潰すため、多様性が強制される。
  • 局所ペナルティ化: 1 点選ぶごとに、その周囲の獲得関数にペナルティを掛ける。
  • q-EI / q-UCB: バッチ全体の同時価値を最適化するモンテカルロ型バッチ獲得関数（BoTorch などに実装）。
# Kriging Believer の骨格
batch = []
from copy import deepcopy
gp_b = deepcopy(gp)   # clone() では未学習モデルになってしまう
for _ in range(q):
    mu_b, sig_b = gp_b.predict(X_candidates, return_std=True)
    x = X_candidates[np.argmax(expected_improvement(mu_b, sig_b, y_best))]
    batch.append(x)
    gp_b.fit(np.vstack([gp_b.X_train_, [x]]),          # 幻想点で更新
             np.append(gp_b.y_train_, gp_b.predict([x])))

非同期ループはさらに一歩進みます。装置ごとに終了時刻が異なるため、どれかのスロットが空くたびに、完了済みの全結果と実行中実験の幻想値を条件として新しい実験を発行します。

2.5 多目的キャンペーン

実際の材料は複数の物性を同時に満たす必要があります — 固体電解質には高いイオン伝導度と電気化学的安定性、太陽電池吸収層には適切なバンドギャップと長いキャリア寿命、そしてすべては最終的に安価で安定でなければなりません。目的が競合すると単一の最良試料は存在せず、目標はパレートフロント — ある目的を改善すると必ず別の目的が悪化する試料の集合 — になります。

  • スカラー化: 目的を 1 つのスコアに畳み込む（重み付き和、望ましさ関数の積）。単純だが、重みを事前に決める必要がある。
  • 期待ハイパーボリューム改善量（EHVI）: パレートフロントが支配する超体積を最も増やすと期待される実験を選ぶ — 原理的な多目的獲得関数で、BoTorch/Ax に実装されている。
  • 制約: 絶対条件（「安定窓 > 4 V」）は独自の確率モデルを持つ実行可能性制約として扱い、獲得関数に実行可能確率を掛ける。

多目的閉ループの実例には、ポリマーブレンドの伝導度と機械的強靭性の同時最適化や、ナノ粒子の光学スペクトルとサイズ分散の同時最適化があります。

導入事例に共通する実務的教訓が 2 つあります:

  1. プランナーがボトルネックになることは稀 — 統合、パース、ハードウェアの信頼性がエンジニアリング労力の大半を占める（第 3 章）
  2. 化学を探索空間に埋め込む: 組成の合計を 100% に拘束する、対数濃度で扱う、溶媒選択にカテゴリカーネルを使う — こうした工夫は、凝った獲得関数よりもデータ効率を改善する

2.7 本章のまとめ

  • SDL の頭脳 = 代理モデル（予測 + 不確かさ）+ 獲得関数（次の実験の価値）
  • 小規模で高価なデータセットには GP が支配的。EI/UCB が標準的な獲得関数で、探索と活用をトレードオフする
  • 並列ロボットに実験を供給するにはバッチ・非同期計画（Kriging Believer、q-EI）が必須
  • 多目的キャンペーンはパレートフロントを狙い、EHVI が原理的な獲得関数
  • 成熟したソフトウェア（Ax/BoTorch、Gryffin、NIMO）があるため、プランナーをゼロから書くことは稀

演習問題

  1. 概念: GP が候補 A: μ=80, σ=2、候補 B: μ=70, σ=15 と予測した（現在の最良値 y=82）。EI はどちらを好みやすいか、理由とともに述べよ。κ=0.5 の UCB ではどうか。
  2. コーディング: 上記の Kriging Believer の骨格を 1 次元のトイ関数に実装し、q=4 のバッチが EI 上位 4 点よりも空間的に分散することを示せ。
  3. 設計: 電池材料キャンペーンで、界面抵抗をしきい値以下に保ちながらイオン伝導度を最大化したい。プランナー構成（モデル、獲得関数、制約処理）を提案し、各選択を正当化せよ。
